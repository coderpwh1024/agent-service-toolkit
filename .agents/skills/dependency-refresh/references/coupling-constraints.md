# 耦合约束与注意事项

本文档记录实际刷新过程中遇到的项目特有约束。处理解析器冲突或意外 CI 问题前应先
查阅本文档，并在遇到新问题的同一 PR 中补充记录。这里只记录要点；当前具体情况应以
解析器和发行说明为准进行验证。

## uv 与冷却机制

- **相对值 `exclude-newer` 需要较新的 uv。** 旧版 uv 会发出警告
  （`Failed to parse pyproject.toml during settings discovery`），忽略整个
  `[tool.uv]` 表，并在重新锁定时悄然删除 `uv.lock` 中的冷却元数据。始终使用仓库固定
  的 uv 版本执行锁定。
- **冷却期冲突看起来像无法满足的固定版本。** `uv lock` 会失败并显示
  `exclude-newer` 提示。这是在执行策略，而非发生故障：应推迟升级；仅对于安全修复，
  可按 SKILL.md 添加带说明的临时 `[tool.uv.exclude-newer-package]` 覆盖项。
- **重新锁定会再次获取索引元数据，** 因此即使版本没有变化，无关的 wheel 条目也可能
  从 `uv.lock` 中移除。对于支持的平台没有影响。

## GitHub Actions

- **Node 运行时弃用会表现为 CI 警告，而非锁文件冲突，** 固定的 `@vN` 引用也不会
  自动升级。检查每个 action 的 `runs.using`，包括组合式 action 中嵌套的 `uses:` 行，
  并升级到使用当前运行时的主版本。注意随版本升级一同出现的行为变更，例如
  `docker/build-push-action` 默认启用来源证明。
- **某些 action 会出于供应链加固目的停止发布浮动主版本标签**（例如 v8 起的
  `astral-sh/setup-uv`），此时必须固定到确切版本。

## LangChain / LangGraph 生态系统

- **`langchain` 与 `langgraph` 必须同步升级。** 元包将 `langgraph` 限制在较窄范围内，
  因此两者都不能单独升级到超出另一方约束的版本。
- **`langgraph`、`langgraph-checkpoint` 与各检查点存储器包**应作为一个耦合单元升级。
  检查点存储器主版本可能改变已存储检查点的兼容性或删除 API（mongodb 存储器删除了
  异步类，`src/memory/mongodb.py` 对此进行了衔接）。测试套件模拟了真实后端，因此需要
  手动验证新存储器仍可读取旧检查点。
- **LLM SDK 升级具有链式效应：** `langchain-<provider>` 会引入较新的提供商 SDK，
  后者又会提升自身依赖下限（例如 `openai` → `jiter`）。应准备好同步升级整条依赖链。
- **提供商适配器可能限制共享库的版本**（例如 `langchain-google-vertexai` 限制
  `pyarrow`）。无法提升的下限通常由此类限制导致。
- **适配器主版本可能改变真实 API 行为**（传输方式、结构化输出默认值），而伪模型
  端到端测试无法覆盖这些行为。在生产环境采用升级前，应使用真实提供商密钥验证相关
  路径。
- **本仓库对 `langfuse` SDK 的使用范围很小**（仅 `CallbackHandler` +
  `auth_check()`），因此 SDK 主版本升级通常只涉及版本更新；重量级自托管基础设施要求
  属于 Langfuse *服务端*，本仓库并未内置服务端。

## 工具与其他事项

- **`ruff` 格式化器的输出可能随次版本升级而变化。** 预计可能出现一次性的
  `ruff format` 差异，而不只是新增 lint 规则。
- **未设置上限的开发工具主版本会通过 `uv lock --upgrade` 大量进入。** 可临时设置
  上限，避免破坏性主版本混入常规刷新，并在专门的升级中解除上限。
- **`numpy` 会率先放弃旧 Python 版本。** 决定何时放弃旧 Python 次版本时，它的版本
  下限通常是遇到的第一个硬性约束。
- **不要把解析器选出的版本写成依赖要求。** 过去在对齐固定版本时，曾为没有任何依赖方
  要求的纯传递依赖项设置 `>=` 下限，后来阻碍了无关升级。纯传递依赖项根本不应出现在
  `[project] dependencies` 中。

## Python 解释器

- **验证新的 Python 次版本时，应使用稳定补丁版本而非 rc 版本。** rc 构建版本曾遇到
  已经修复的解释器/pydantic 缺陷，这些问题在稳定版中无法复现。

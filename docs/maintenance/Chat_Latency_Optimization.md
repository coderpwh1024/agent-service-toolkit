# 主对话首 Token 与缓存优化验证

2026-10-26，使用实际 Nacos 模板与北京百炼端点，对普通对话的模型阶段做隔离对照。每组 5 次，三类合成问题轮换，各组交错运行；统一关闭 thinking、启用流式用量、输出上限 256 Token。不执行模型选择的工具，不提交真实视频或邮件，不读取真实用户对话。API 请求使用同一模型的复用客户端。

这里测量的是模型 API 调用到首个非空正文片段，不含 Mem0 检索、入口鉴权、ASR 或 TTS，与完整服务的首字日志口径不同。隐式缓存不能关闭，因此不能把每组第一次视为冷请求。5 次样本只能描述当次结果，不能证明统计显著或提供可靠的 P95。

| 方案 | 有效样本 | 首字平均/ms | 中位数/ms | 最小/ms | 最大/ms |
| --- | --- | --- | --- | --- | --- |
| 原模板与原布局，Max 隐式缓存 | 5 | 1004 | 1017 | 752 | 1370 |
| 精简模板与固定前缀，Max 隐式缓存 | 5 | 1087 | 1127 | 928 | 1191 |
| 精简模板与固定前缀，Max 显式缓存 | 5 | 1250 | 1024 | 897 | 1754 |
| 精简模板与固定前缀，Flash 隔离评估 | 5 | 675 | 658 | 568 | 816 |

输入从约 3906–3912 Token 降至约 2048–2054 Token；角色模板从 4849 字符精简到 1742 字符。显式缓存首个请求创建 2008 Token，后四次均命中 2008 Token，占对应输入约 98%。但本组没有证实 Max 首字变快：精简隐式组平均略高于原组，显式组出现较大时延波动。因此正式配置继续关闭显式缓存，不宣称 Token 减半等于首字减半。

正式默认模型保持 qwen3.8-max。Flash 首字更快，但真实模型回归中能查询数量，却未正确保存和修改视频草稿，故不注册到服务模型目录、不自动切换。评估脚本直接创建隔离客户端，保留后续复测能力。

Max 的合成多轮验证覆盖重复低信息量聊天、明确结束、不可信记忆注入、视频数量、保存十秒草稿、修改为十五秒及取消。修正主工具规则中对草稿修改的提示后，视频状态与参数均符合预期，创建和编辑提交次数均为零。聊天自然度、表述和重复倾向仍是概率性行为，少量样本不构成任意输入下的质量保证。

Nacos Prompt CLI 将 mem0-chat-system 发布为 1.0.1；CLI 与 SDK 回读逐字一致，其他五条记忆模板保持原版本。角色模板 SHA-256：`fb26a4647c7cb3284e84f092e303111ed032d7843b46f94408a7c0b930e0290b`。服务继续只从 Nacos 加载模板，没有本地正文回退。

复现脚本为 scripts/benchmark_chat_latency.py，从仓库根目录使用 `PYTHONPATH=src uv run python scripts/benchmark_chat_latency.py` 启动。比较历史版本时，应先用 Nacos Prompt CLI 获取对应模板，再显式传入候选路径；报告只包含指标与内容摘要，不保存提示词和回答正文。

## HTTP 入口回归与默认思考配置

重启后，三次显式关闭 thinking 的完整 HTTP 流式首字为 1.727、1.401、1.985 秒，平均 1.704 秒，均正常收到回答且完成记忆写入。该批包含检索、鉴权等开销，未显示比历史小样本 1.42 秒更快。视频数量查询收到真实 `video.count` 事件。联网研究实际触发子图，但外部搜索超过既有 5 秒限制，返回受控超时提示；未伪报搜索成功。

额外检查发现，不传 thinking 参数的普通 HTTP 入口曾沿用供应商默认行为，模型首字日志为 26.701 秒。现增加独立 `CHAT_LLM_ENABLE_THINKING` 配置，普通聊天默认显式关闭，保留请求 `enable_thinking=true` 与原有语音覆盖；不更改其他 agent 的默认推理策略。该配置变更与缓存命中优化分别验证，不能将此延时差异归功于缓存。

最终按正式默认配置重启并复测，不传 `enable_thinking`：单字输入的完整 HTTP 首字为 1.643 秒；三次普通对话为 1.432、1.337、1.359 秒，平均 1.376 秒，均正常收到最终回复。对应的主模型首个正文片段平均为 1.065 秒。三次输入均为 2048 Token，模型上报缓存读取 2048 Token；这只说明相同合成提示词在本批请求中命中了缓存，不能推断所有对话都会如此。历史完整 HTTP 首字均值约 1.42 秒，本次小样本差异不足以证明稳定提速。上述 HTTP 首字不含 ASR 倾听和 TTS 播放，完整回合还包含后续记忆写入。

## 进一步排查

上述三次普通请求的 Mem0 检索分别耗时 294、180、348 毫秒，均返回零条记忆；这几乎覆盖了首字前的本地准备时间。主模型首个正文分别耗时 1107、1122、966 毫秒。因而在保留每轮检索和现有主模型的条件下，即使消除其余本地开销，也不能把首字稳定压到一秒以下。不能依据本批空结果就跳过其他用户的记忆检索。

使用相同提示词和工具定义、关闭 thinking、交错测试三种合成普通问题：`qwen3.8-max` 的首字为 1097、1100、940 毫秒，平均 1046 毫秒；`qwen3.7-plus` 为 841、1445、983 毫秒，平均 1090 毫秒。Plus 的一次隔离视频流程正确完成数量查询、保存十秒草稿、改为十五秒和取消，且没有真实提交；但它没有展示首字优势，样本量也不足以保证任意工具请求正确。故不切换默认模型。若目标是稳定低于一秒，需要进一步评估更快模型或改变检索与工具路由语义，并对语音、联网搜索、记忆及视频逐项回归。

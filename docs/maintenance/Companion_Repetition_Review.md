# 重复对话提示词分析

## SQL 样本与方法

2026-10-16 14:51（北京时间）使用应用已有的配置加载方式，连接当前 `local` 环境实际配置的 PostgreSQL。连接设置只读事务和语句超时；仅执行查询，没有修改检查点、记忆或业务表。未导出原始聊天、用户标识或连接凭据。

按 `app_thread_owners.agent_id = mem0-chatbot` 限定范围，从 `checkpoints` 的根命名空间为每个线程选取最新检查点，最多读取 100 个，实际得到 34 个。使用现有 checkpointer 解码完整历史，每个线程只分析一次，避免把多个检查点中的累积历史重复计数。

这些会话最新检查点的时间范围为 2026-10-13 07:02:37 至 2026-10-16 06:45:12 UTC。范围描述的是快照更新时间，不是每条消息的发生时间。分析保留各快照内完整对话顺序，不把它当作严格按消息日期筛选的数据集。

排除 647 条语音播放状态记录后，保留 1,012 条用户消息和 488 条助手消息。两者数量不同，不能假设每条输入都有完整可见回答。

相邻用户消息去除标点、空白并统一大小写后相同，计为完全重复；不同且两边至少四个字符、字符序列相似度不低于 0.78，计为文字近似。文字近似只用于找候选，不等同于语义相同；新增条件、事实核对和明确复述需要结合上下文区分。

| 观察项 | 结果 |
| --- | --- |
| 完全重复输入 | 42 次 |
| 文字近似输入 | 27 次 |
| 上述输入后有可见助手回复 | 65 次 |
| 这些回复的字符数中位数 | 7 |
| 这些回复不足 40 字符 | 56 条 |
| 这些回复不足 10 字符 | 37 条 |
| 与同线程上一条重复输入对应回复完全相同 | 20 条 |
| 这些回复以问题结束 | 16 条 |
| 这些回复再次让用户提供话题或需求 | 6 条 |

统计字符数包含标点与换行，不等同于汉字数。排除简短确认输入后，仍有 62 条重复输入对应回复，字符数中位数为 6.5，因此极短回复不能仅由“是／对／嗯”等确认造成。

本批消息没有匹配“无聊／没意思／没劲／陪我聊”等筛选词，不能声称已观察到实际用户反复说“无聊”的样本。用户所指的无聊型、低信息量互动，在这些记录中主要体现为重复负面短句、重复确认与短句试探；直接表达无聊的场景另用合成对话验证。

## 问题与提示词调整

历史中能看到连续极短确认、重复客服追问、对短确认过度解读，以及语音中断记录影响上下文理解。快照没有保存每次运行使用的系统提示词版本，因此不能把全部历史表现归因于某一版提示词，也不能直接充当严格的前后对照。

修改前的提示词同时强调普通聊天一到三句话，以及没有新任务时简短、中性承接；这为模型退化成连续确认词留下了明显空间。仅增加字数与禁止重复的条款后，小规模生成仍出现相似开头、对重复次数的点评和同类故事复用，说明内容量与回应多样性需要分别指导。

最终将分散规则合并为七个部分，系统提示词由本轮修改前的 6,650 字符整理为 4,849 字符，重点如下：

- 普通陪聊默认约 80–180 个汉字、四到六句，有具体展开；重复或短输入不触发自动压缩。
- 提问前先提供内容，用户不接话时回复本身也有价值，不反复索要话题或征求讲故事的许可。
- 根据上下文分开处理没理解、新条件、无聊、情绪、关系确认与低信息量输入。
- 历史助手回复只表示已经说过什么，不能作为下一轮照搬的模板；检查内容、结构与结尾是否重复。
- 对负面短句保持从容，减少争辩和反击，既不连续敷衍，也不点评输入次数或猜测用户动机。
- 短确认只承接紧邻内容；播放状态不代表用户发言或认可，明确停止和准确复述仍然优先。
- 趣味创作明确为想象，不为追求刺激杜撰科学、医学、心理学知识或个人经历。

生产代码只修改 `SYSTEM_PROMPT`。没有增加相似度判断器、回复后处理、历史裁剪、模型参数或数据库变更。上面的相似度计算只用于本次只读分析。

## 验证范围

真实模型验证使用当前配置的 `qwen3.8-max`，固定 `enable_thinking=false`、单次最多 700 输出 token，仅发送合成对话。修改前后使用相同模型、参数和固定历史，没有把真实用户聊天发送给评估模型，也没有通过聊天服务写入新检查点或记忆。

固定场景包括重复无聊、重复负面短句、同意讲故事后的短确认、只想倾诉、相似问题新增限制和明确停止。另进行两组各五轮的连续生成：重复无聊，以及五次相同负面短句；每轮把该模型上一轮生成的回答带入历史。

以下是同一组固定历史下，修改前提示词与最终提示词各生成一次的结果。字符数包含标点和换行：

| 合成场景 | 修改前 | 最终版 | 人工观察 |
| --- | --- | --- | --- |
| 反复无聊，要求主动提供内容 | 45 | 180 | 从很短的趣味陈述展开为具体观察；仍有结尾追问 |
| 同一句负面短句重复三次 | 14 | 127 | 有内容展开，但仍出现点评输入次数和索要具体问题 |
| 同意讲故事后连续短确认 | 140 | 223 | 直接开始故事，没有重新索要类型 |
| 重复烦闷，明确不要建议 | 38 | 120 | 对已知难处展开，没有转为操作建议 |
| 相似问题新增不看屏幕、不做饭限制 | 39 | 241 | 回答遵守新增条件，但篇幅超过软目标 |
| 明确停止 | 8 | 9 | 保持一句话结束，没有追加内容 |

排除停止场景后，五个固定场景的回复字符数中位数从 39 增至 180。连续五轮无聊的回复为 193、208、176、167、172 字符；连续五轮相同负面短句的回复为 118、92、135、193、181 字符。两组没有连续完全相同的输出，也没有退化成极短确认。

仍存在明确缺口：连续负面输入后，模型会违反提示词去评论次数、猜测动机并复用相似收尾；无聊场景中仍可能擅自替用户决定不再找话题。部分趣味陈述也需要进一步核验事实依据。因此这版只能确认普通场景的内容量有改善，不能宣称连续重复下的语义多样性和所有边界要求均已解决。已保持仅修改系统提示词的范围，没有用回复重写、过滤器或修改模型参数掩盖这些结果。

字数增加只能说明内容量变化，不能单独证明聪明、自然或有情绪价值。还需人工检查是否推进内容、是否照搬示例、是否出现不必要追问、是否杜撰事实及是否尊重停止。此次样本量小、没有固定随机种子，不能作为统计显著的效果结论，也不能保证任意输入下都无重复。

回归验证：相关单元测试 64 通过；全量测试使用 `--import-mode=importlib` 避免仓库已有同名测试模块的收集冲突，结果为 617 通过、6 跳过。Ruff 格式与 lint、Pyrefly 类型检查、修改文档的 Markdown 检查通过。静态 AST 对比确认生产文件除 `SYSTEM_PROMPT` 外没有行为代码变更。没有修改数据库 schema 或持久化路径，因此未运行真实基础设施冒烟测试。
